Watch out

Look-alikes and double meanings

These terms share a word or sound similar, but mean different things. Exam questions and interviews love them.

Two-phase commit vs two-phase locking

2PC

Agreement across nodes

Makes several nodes in one transaction either all commit or all abort. It's about atomicity.

Example: an order row in one database and a stock row in another must commit together.

2PL

Isolation between transactions

A transaction locks everything it reads or writes and keeps the locks until it ends. It gives serializable isolation.

Example: one transaction is reading a row, so another can't change it until the first one finishes.

Tell Commit = nodes agreeing (Chapter 8's distributed part). Locking = transactions waiting their turn.

Linearizable vs serializable

Linearizable

Recency on one object

The system acts like one copy of the data, and every read sees the latest completed write.

Chapter 10. Needed for leader election and uniqueness checks.

Serializable

Isolation for many objects

Concurrent transactions give the same result as running them one at a time in some order. Stale reads can still be allowed.

Chapter 8. Prevents race conditions like write skew.

Tell Linearizable is about when (real-time order). Serializable is about whether transactions interfere.

The two meanings of “atomic”

Concurrency

Happens at one instant

Other threads never see the operation half done. That's the sense in “atomic compare-and-set” and in linearizability.

Transactions (the A in ACID)

All or nothing

A group of writes either all commit or all roll back, even after a crash. Whether others see it midway is isolation, not atomicity.

The two meanings of “skew”

Load skew

Uneven shards

Some shards get far more data or requests than others: hot spots. Chapter 7.

Timing skew

Things seen out of order

Events appear in an unexpected order: read skew and write skew (Chapter 8), clock skew (Chapter 9).

Replication vs sharding

Replication

Same data, many nodes

Copies, so the data survives a node going away and reads can spread out.

Sharding

Different data, many nodes

Splitting a dataset that's too big for one machine. Usually combined with replication: each shard has replicas.

“Primary” means two things

Primary (replica)

The leader

The one replica allowed to accept writes.

Primary key

A record's identifier

The unique value that identifies a row or document, usually generated by the system.

  • Node also means two things: a process in a distributed system (most of the book), and a vertex in a graph (Chapter 3).
  • Log covers four ideas: a write-ahead log (crash safety), log-structured storage, a replication log, and an event log (a stream).
  • Cache vs derived data: every cache is derived data, but not all derived data is a cache. A cache is usually incomplete; an index or materialized view covers all the data.
  • Fault-tolerant ≠ never fails: it means the system recovers by itself when a part fails.
